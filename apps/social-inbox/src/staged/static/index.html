Social Inbox RC

Declared permissions

  • vault.identities.read lists public metadata for granted social signing identities.
  • vault.identities.create creates an app-owned preview identity without exporting private key material.
  • vault.identities.use requests bounded social-message signatures from AppVault.
  • content.fetch fetches bounded social outbox JSON selected by the user.
  • content.subscribe manages app-owned USK social source subscriptions.
  • content.insert.app-document queues generated social outbox snapshots.
  • queue.read reads upload queue summaries for outbox publication.
  • queue.write creates generated outbox publication inserts.
  • app.data.read restores bounded sources, summaries, drafts, and read state.
  • app.data.write saves bounded app-owned social inbox state.
  • app.services.read discovers local app-service descriptors and grant state.
  • app.services.call requests and invokes approved local app-service grants.

Reference app scope

This RC reference app demonstrates a social/mail-like layer outside the daemon by combining AppVault identity, local message threading and read state, bounded signed message documents, content insert/fetch/subscriptions, app data, and operator-approved Trust Graph Local RC service annotations.

  • It is not full WoT and is not compatible with old WebOfTrust plugin APIs.
  • It is not Freetalk, Sone, Freemail, and it is not encrypted mail or multi-recipient private messaging.
  • It does not add a daemon-core message store, moderation service, plugin ABI, or network protocol change.

Import behavior
Unsupported, malformed, oversized, and signature-mismatched entries are rejected without storing raw bodies or signatures.

Beta readiness

Scoped social inbox RC

  • No sources or messages show empty states; subscription, import, and trust-score failures use bounded copy.
  • Retry source refresh, resubscribe, reload trust score state, or refresh queue from the controls on this page.
  • App-data export/import covers sources, summaries, read state, and drafts. Schema 1 changes are additive.
  • Support uses catalog metadata, optional Trust Graph grant state, and redacted-summary-only diagnostics without raw messages.
